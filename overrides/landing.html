The fleet

A seat is a role an agent takes, with its duties and its rights written down.

The tool knows the Owner, and three seats with their rights built in — planner ask · close · triage, reviewer triage, builder none. Four rights, each a front-matter transition the gate sees in a diff; anything else is open to every seat.

  • Planner

    the skipper

    turns the Owner's direction into trackers, and puts the agents' open questions to the Owner, one sentence each.

  • Builder

    the shipwright

    builds one change from its tracker, in a worktree of its own, and never accepts its own work.

  • Reviewer

    the inspector

    reads a branch against its tracker and writes READY, or what must change. It never merges.

  • Specialists

    (customizable)

    called in when the work needs them. Name your own in [seats], with the rights [rights] gives them.

A seat's charter — how it thinks, a bold Planner against a steady one — is <tracker dir>/seats/<name>.md, read by the agent at start, never by the gate.

--next
A cold start in one command: what to work on, and what is true now.
--new "…"
Look before you file: the closest trackers come first. The default is a slice of one that exists.
--triage
The seat judges, the command applies — tier, rank and park are written from the worksheet, never by hand.
--check
The gate on every commit refuses what contradicts itself.
  1. The tracker is canonical. Never a side plan, a chat or a TODO comment.
  2. Look before you file.
  3. An id never changes and says nothing that can.
  4. The seat judges, the command applies.
  5. Close out by asking what this made obsolete — and delete it in the same change.

Your agents set it up

Nothing is taken away: the path for a fleet that already runs a system of its own is filed (FM-026) and coming.

  1. They fetch shoalmark at a release tag and put a pinned copy in the repository, every file with its checksum (--vendor).
  2. --init writes the configuration, the triage file and the agents' contract.
  3. The agents read the contract and file the work: one Markdown file per work item.
  4. You write three lines in your own words: what the repository is for, what is true when it works, what nobody may do to get there. Then you set up your signature, once.

One sitting, fifteen minutesat the time you choose. The invite comes as a calendar file.

The rest comes to youevery session's last message ends with what waits for you. You open nothing.
